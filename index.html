Field-study question

AI가 제조 현장에서 실제 가치를 만들려면 defect를 찾는 것에서 끝나는가, 아니면 분석·지식·조치까지 이어지는 closed loop가 필요한가?

01 · THREE LAYERS

세 기업을 하나의 품질 workflow로 연결

DetectDelvitech HORUS
TraceGitLab
KnowledgeSionic AI STORM
02 · AI INSPECTION

False call과 repeatability까지 봐야 하는 자동 검사

HORUS는 SMT/PCB manufacturing의 3D SPI와 AOI를 AI 기반으로 통합하는 방향의 inspection platform입니다. 현장에서는 defect classification 자체뿐 아니라 recipe setup, false call, 반복성, line 확장 시 consistency가 품질관리에서 중요한 문제라는 점이 인상적이었습니다.

HORUS는 wafer front-end inspection tool이 아니며, 이 프로젝트는 검사 자동화의 transferable quality concept을 반도체 업무에 연결합니다.

03 · ENGINEERING TRACEABILITY

분석 script도 품질관리 대상이 될 수 있다

GitLab의 version control, CI, root-cause workflow를 보며 SPC·equipment-log·defect analysis code가 현장 decision에 쓰인다면 code 자체도 검증·변경이력·review가 필요한 engineering asset이라고 생각했습니다.

04 · QUALITY KNOWLEDGE

SOP와 과거 불량 이력을 찾는 시간도 response time의 일부

Sionic AI STORM의 enterprise RAG / no-code agent 기능을 SOP, OCAP, FMEA, 8D/CAPA, equipment manual, defect history와 연결하는 품질 지식 agent use case로 확장했습니다.

05 · QUALITY LOOP

AI value comes from closing the loop

Detect
Analyze
Retrieve
Act
Feedback

실제 제조 AI는 단일 모델이 아니라 검사 데이터, 분석 logic, 표준 지식, engineer approval, process feedback이 연결될 때 의미가 있다고 정리했습니다.

06 · CAREER TAKEAWAY

AI developer가 아니어도 AI를 현장에 연결할 수 있어야 한다

양산/품질 엔지니어에게 중요한 것은 AI model을 직접 개발하는 것보다 어떤 data를 믿을지, 어떤 false call을 관리할지, 어떤 분석을 재현 가능하게 만들지, 어떤 output을 process action으로 연결할지를 판단하는 능력이라고 느꼈습니다.
